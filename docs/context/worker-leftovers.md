# Worker leftovers

A running list of things workers and smoke tests leave behind outside the repo. Workers append what they leave. Nobody deletes entries by hand.

## Cleanup by worker kind

`close_worker` scopes home-directory cleanup by `HarnessId`, and runs it only after a successful close whose plan includes `RemoveWorktree` (`cleans_claude_leftovers` and `cleans_cursor_leftovers` in `crates/core/src/`). A markers-only close does not clean home directories. Cleanup failures add warnings to the result rather than failing the close.

- **`Claude`:** removes the worktree's transcript folder `~/.claude/projects/<mangled path>` and its trust entry under `projects` in `~/.claude.json`. The mangled path follows Claude Code: every UTF-16 unit that is not an ASCII letter or digit becomes `-`, and a name over 200 characters keeps its first 200 and gets `-<base36 hash>` appended. The trust file is rewritten through a temp file unique to each close, while ralph holds a lock on `ralph/claude-json.lock` in the OS per-user data folder (`~/Library/Application Support` on macOS, `$XDG_DATA_HOME` or `~/.local/share` on Linux). Every close uses that one path whatever `--store` or `RALPH_CONFIG_DIR` says, and the lock file stays after close so all closes lock the same file. A concurrent change retries the rewrite up to three times, then skips it with a warning. Without `~/.claude.json` the trust step is skipped and no lock is created; without a per-user data folder it is skipped with a warning. Successful cleanup leaves neither item; a missing worktree or a cleanup warning can leave them behind. The folder and file follow the claude ralph started (`claude_leftovers::spawned_claude_files`): `[claude] config_dir` when set, else a `CLAUDE_CONFIG_DIR` in the chat's environment (`<dir>/projects/...` and `<dir>/.claude.json`), else `~/.claude` and `~/.claude.json`. As in claude, a relative value starts at the worktree, and an empty value moves the folder to the worktree but keeps `~/.claude.json` (claude reads `CLAUDE_CONFIG_DIR || home` for that file). Close reads that variable in the chat process (`Workers::close`). A tmux claude takes its environment from the tmux server and its login shell, not from the chat, so for `Claude` this is a best guess: when the two differ, close cleans the wrong folder and leaves the real one. Usage rows of a tmux claude are not affected, because they use the transcript path the Stop hook reports. Close also derives the paths again from the chat's current `[claude] config_dir` and `CLAUDE_CONFIG_DIR`, not from the values at spawn. If the chat restarted with a different value since the spawn, close cleans the wrong place, and the real transcript folder and `.claude.json` entry stay behind.
- **`ClaudeHeadless`:** runs one `claude -p` stream-json child per worker and leaves the same `~/.claude/projects/<mangled path>` transcript folder and `~/.claude.json` trust entry as `Claude`; claude keys the transcript by the session id ralph passes with `--session-id`. Its owner record lives in `<store>/claude-headless/<id>` and its session record in `<store>/claude-headless-session/<id>`. The session record is written in `start` before turn 1 (so a turn-1 crash is resumable), rewritten in `adopt`, and removed when init fails or the worker is not adopted. Close drops stdin, stops the process group, sweeps the tree and removes the owner record and the session record. After a successful close whose plan includes `RemoveWorktree`, `cleans_claude_leftovers` removes the transcript folder and trust entry exactly as for `Claude`.
- **`Cursor`:** runs `agent -p` per turn (and `agent acp` only to resume an old ACP session record), never `claude`. It leaves `~/.cursor/projects/<slug>` (plus a hashed socket dir there when the path is long) and `~/.cursor/acp-sessions/<id>/`. Close removes project paths derived from the worktree's real path and sessions whose `meta.json` `cwd` exactly matches the worktree or its real path, and lists each removed path in its result. It keeps the project folders, with a warning, when another known path (a `git worktree list` entry or an `acp-sessions` `cwd`) maps to the same slug or the git listing fails. This does not restore `~/.cursor/cli-config.json` changes made by `agent acp`. Close also removes `~/.cursor/chats/<md5 of the real path>`, where every `agent -p` run writes `<uuid>/meta.json`. Close also stops the leaked `worker-server` (`ralph_core::worker::worker_server_groups`). Both `agent -p` and ACP turns with shell calls leave `node …/cursor-agent/versions/<v>/index.js worker-server` running with parent 1, in its own process group, so the group kill of the host misses it. It holds `~/.cursor/projects/<project dir>/worker.sock` and starts a language server tree in its group. ralph selects a process only when its command contains `cursor-agent/versions/` and ends in `worker-server`, and `lsof` shows it holding the `worker.sock` of this worktree's socket project dir. It never matches by name alone, so the server of another chat's worktree stays. ralph sends TERM to the whole group, waits, then KILL. The sweep runs only when a `-p` worker host shuts down and in close cleanup (the same close that removes the worktree, for ACP and `-p` workers), never per turn, because `-p` turns reuse the server. An ACP worker that closes without removing its worktree leaves the server running.
- **`Opencode`:** closes only that worker's session, evicts its worktree location and removes its worker files plus worktree/branch. It never scans or deletes `~/.cursor` or Claude home-directory data, and does not stop the shared `opencode serve`, even for the last worker. No general cleanup of opencode's own home-directory data is implemented.

See [ralph chat](ralph-chat.md#mcp-tools) for close steps and safety checks, and [Headless workers](headless-workers.md) for hosting kinds, compatibility and chat-owned host shutdown.

Ralph reads these transcripts only to write worker usage rows (GUZ-1258, `worker_usage::record_session`), never to clean up: a tmux `Claude` worker reads the `transcript_path` its Stop hook reports (`worker_mcp::run_stop_hook`), and a `ClaudeHeadless` worker reads `<claude dir>/projects/<mangled path>/<session_id>.jsonl` at each turn end, at claude exit and at close, before close removes the folder (see [Headless workers](headless-workers.md)).

## Kinds

1. Trust entries in `~/.claude.json` for paths that no longer exist.
2. Transcript folders in `~/.claude/projects/<path>`, where every character of the path that is not an ASCII letter or digit becomes `-`.
